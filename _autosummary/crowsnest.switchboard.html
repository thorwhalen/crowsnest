crowsnest.switchboard#

The switchboard: any session or plain process messages a live session, with no model turn.

Claude Code gives every session an inbox socket (its registry record’s messagingSocketPath), where other sessions on the machine deliver messages (https://code.claude.com/docs/en/cross-session-messaging). A message arriving there is read between tool calls during a turn, and starts a new turn when the session is idle. Inside a session, Claude’s own SendMessage tool reaches it. This module reaches it from anywhere else too: a scheduler, the courier, a connector, a script, or a session that wants the message on the record. That makes dispatch a shared facility rather than the watching session’s privilege: the lookout becomes one caller among many.

tell() refuses a session that cannot take a message well, hands the text to the transport, and appends a message line to the event log (crowsnest.eventlog). deliverable() judges the status only:

  • idle takes a message;

  • busy (or shell) only with busy_ok: Claude Code hands it over between two tool calls, which never interrupts a tool but does change what the turn was doing;

  • waiting never: the session cannot act until its person answers, and a message would sit on top of the question it is asking them; nor any other status.

The transport is the deliver= seam, (session, text) -> None, raising Refused (or OSError) when it cannot deliver. Its default, socket_post(), writes one JSON line, {"type": "user", "message": {"role": "user", "content": TEXT}} (the shape Claude Code’s own debug log prints for injecting a message), to the session’s socket on this machine, and only after checking that the socket is held by the very process the registry record describes: the record is this host’s (pidDomain), the peer’s pid is the record’s, and that pid started when the record says (procStart), so a pid reused after a crash is never mistaken for the session. Another machine’s session (a synced home), a spare or a bare-mode one is refused by it; a transport for another host takes the same session and reaches it there.

Whether the session accepts it is the receiver’s setting, crossSessionInbound: with accept every message is delivered; with none set, a session that bypasses permission prompts holds a message from a process that asserts no permission class until its person approves it, and a non-interactive one lets it expire. inbound_of() reads the receiving home’s user setting, so a caller with no person at hand (the courier) can route elsewhere when it is not accept.

crowsnest.switchboard.same_process(session)[source]#

Is session.pid still the process that registered session?

Compared through the start time Claude Code recorded: ps’s on macOS, /proc’s on Linux (crowsnest.guard.same_process()). A record without one, or a platform where neither works, cannot be confirmed, and the answer is False: delivering to a stranger is the error this exists to prevent.

Return type:

bool

crowsnest.switchboard.socket_post(session, text, *, timeout=5.0, confirm=<function same_process>)[source]#

Post text as one user message to session’s inbox socket on this machine.

Refuses a session with no socket, one from another machine (its pid_domain, crowsnest.registry.is_local()), a path that is not a socket we own (lstat, so a symlink is refused), a connection whose peer is not the record’s pid (or whose peer the OS will not name), and a pid that is no longer the process that registered it (confirm, checked once connected). The connection is opened only once the text is ready (Claude Code closes one that sends no complete line within 30 seconds) and closed right after.

Return type:

None

crowsnest.switchboard.tell(session, text, *, sender=None, reply='', busy_ok=False, deliver=None, events_path=None, extra=None, note='')[source]#

Post text to session; {"to", "status", "sender", "at", "inbound"}.

sender signs it (default: the calling session’s label, else ANONYMOUS); reply is a last line telling the receiver how to answer. Raises Refused for a status deliverable() refuses, for empty or oversized text, and when the transport cannot deliver. deliver is the transport, (session, text) -> None, default socket_post(). extra adds fields to the event line (an intent id). inbound is the receiver’s crossSessionInbound (inbound_of()). note is a line under the sender’s that says what the text is (envelope()). The event line records the claimed from and, in by, the session that actually ran this (or ANONYMOUS), which a caller cannot choose.

Once the transport has delivered, nothing here raises: a log line that cannot be written is reported in hook.log, never as a failure, because a caller that retries a failure would deliver the message again.

Return type:

dict
