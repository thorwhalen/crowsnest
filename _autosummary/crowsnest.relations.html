crowsnest.relations#

What relates to what: the sessions and the things they touch, as one typed graph.

The roster is a list and crowsnest.lineage is a tree. Neither answers the questions a person asks of a fleet once it is large: *which sessions are waiting on me, and what else hangs off them? Who is talking to whom? Which of these forty are working in the same repository?* Those are questions about relations, between things of several kinds, and this module is where they become data: nodes with a type, links with a type, and a few rules that derive the relations nobody recorded.

The shape is the nodes and links document the rest of the ecosystem already reads (linked in Python, the zodal-graphs canonical model in TypeScript), so any renderer that reads one reads this:

{"directed": true, "multigraph": true,
 "nodes": [{"id": "session:9f2c", "kind": "entity", "type": "session",
            "data": {"label": "parser", "status": "idle", "interest": 0.9}}],
 "links": [{"id": "waits_on_owner:session:9f2c>owner:me", "type": "waits_on_owner",
            "source": "session:9f2c", "target": "owner:me",
            "data": {"confidence": "recorded", "by": "verdicts", "at": "..."}}],
 "graph": {"as_of": "...", "counts": {}, "types": {}, "skipped": []}}

Topology only: no position, colour or selection ever goes in it. How it is drawn is the page’s business (crowsnest.relations_page), and a second renderer reads the same document.

Nodes (NODE_TYPES): the owner, a session, the machine it runs on, the folder it works in, the repo behind that folder, and what its words refer to: an issue, a pr, a doc. A session’s id is its session id, never its name: a name is not unique across machines or over time (crowsnest issue #42).

Links (LINK_TYPES) are read by sources, and every link says how it is known (CONFIDENCES), the same three classes crowsnest.lineage uses, for the same reason: a guess drawn like a record is worse than no guess.

reader

what it reads, and what it yields

from_sessions()

the roster rows: every session, its machine, folder and repo

from_verdicts()

the triage verdict on a row: waits_on_owner, and why

from_lineage()

the spawn forest: spawned, parent to child

from_references()

the links in a session’s own words: mentions

from_events()

the event log: messaged and told (owner to session)

sources= is the seam: an ordered sequence of callables (rows) -> elements, an element being a node or a link. A node two readers yield is merged, the earlier reader’s values winning, so a reader may add a field to a node another reader made by yielding the same id. A reader for something crowsnest does not own (the documents a session published, the issues that block one another, the sessions another host started) is added by passing it, not by editing this module.

Rules (DFLT_RULES, the rules= seam) derive the relations nobody recorded, and they are data, not code: a Rule is a path of link types to walk, the construction the literature on typed networks calls a meta-path. works_in then in_repo is works on; mentions then of_repo is refers to that repository; works on then works on backwards is *shares a repository with*; spawned walked more than once is descends from. A derived link is always inferred and always carries via, the nodes it went through, so a reader can ask why it is there. A middle node shared by more than max_fanout others is not expanded into pairs (forty sessions in one folder are one hub, not 780 links); what was left out is listed under graph.skipped, never dropped in silence.

A reader or a rule may bring a link type this module does not list: it is carried, and described under graph.types.link (a rule’s by the path it walks), so a renderer can offer it without knowing it in advance. Two readers that yield the same link make one link: counts add up, the latest time and the strongest confidence win.

Interest (the interest= seam) is one number per node in [0, 1]: how much the owner would want to see it now. A view that opens on the few nodes above a threshold and expands on demand is the only way a graph of a fleet stays readable (degree of interest: Furnas 1986; van Ham and Perer 2009). The default scores a session by what triage says it needs and how recently it said so, and gives everything else the score of the most interesting session it is linked to, a little less. A function passed as interest is asked about every node, and what it answers stands.

>>> rows = [
...     {'session_id': 'a1', 'label': 'parser', 'status': 'idle', 'cwd': '/w/mergeset',
...      'project': 'mergeset', 'repo_url': 'https://github.com/i2mint/mergeset',
...      'verdict': {'group': 'needs_you', 'why': 'decision', 'reason': 'squash or rebase?'}},
...     {'session_id': 'b2', 'label': 'docs', 'status': 'busy', 'cwd': '/w/mergeset',
...      'project': 'mergeset', 'repo_url': 'https://github.com/i2mint/mergeset'},
... ]
>>> found = relations(rows, as_of='2026-01-01T00:00:00+00:00')
>>> sorted(found['graph']['counts']['nodes'].items())
[('folder', 1), ('machine', 1), ('owner', 1), ('repo', 1), ('session', 2)]
>>> [(l['source'], l['target']) for l in found['links'] if l['type'] == 'same_repo']
[('session:a1', 'session:b2')]
>>> [l['data']['via'] for l in found['links'] if l['type'] == 'same_repo']
[['repo:i2mint/mergeset']]
>>> top = max((n for n in found['nodes'] if n['type'] == 'session'),
...           key=lambda n: n['data']['interest'])
>>> top['data']['label'], top['data']['ask']
('parser', 'squash or rebase?')

class crowsnest.relations.Rule(name, path, closure=False, symmetric=False)[source]#

Bases: object

A derived link type, as the path of link types that implies it.

path is walked from every node: each step follows links of that type forwards, or backwards when the type is written with a leading ~. Where the walk ends is the other end of the derived link. closure walks the path two or more times instead of once (the links one walk gives already exist). symmetric says the derived relation has no direction, so each pair is given once.

>>> Rule('works_on', ('works_in', 'in_repo')).path
('works_in', 'in_repo')
crowsnest.relations.dflt_interest(found, *, as_of=None)[source]#

How much the owner would want to see one session node now, in [0, 1].

What triage says it needs sets the level; how long ago it said so lowers it, down to a floor (an ask from yesterday still waits, but below one from this hour). A session waiting at a prompt, or mid-turn, is never below a working one. Any other node scores 0 here: relations() gives it the score of its neighbourhood.

>>> now = datetime(2026, 1, 1, 12, tzinfo=timezone.utc)
>>> fresh = {'type': 'session', 'data': {'group': 'needs_you', 'why': 'decision',
...                                      'said_at': '2026-01-01T11:30:00+00:00'}}
>>> stale = {'type': 'session', 'data': {**fresh['data'],
...                                      'said_at': '2025-12-30T12:00:00+00:00'}}
>>> dflt_interest(fresh, as_of=now) > dflt_interest(stale, as_of=now) > 0.6
True
>>> dflt_interest({'type': 'session', 'data': {'status': 'busy'}}, as_of=now)
0.6
>>> dflt_interest({'type': 'repo', 'data': {}}, as_of=now)
0.0

crowsnest.relations.from_events(events)[source]#

A reader of the event log (crowsnest.eventlog.read()): who messaged whom, and what the owner asked of a session from a page or a connector.

A message line (the switchboard writes one per message it delivers) is a messaged link from the sender to the receiver; an intent line is a told link from the owner. Both are counted per pair and keep the time of the latest. A sender or receiver that is not a live session is left out: the log names sessions, and a name is only resolved against the rows read now.

>>> rows = [{'session_id': 'a1', 'label': 'cn'}, {'session_id': 'b2', 'label': 'w1'}]
>>> log = [{'event': 'message', 'from': 'cn', 'name': 'w1', 'at': '2026-01-01T10:00:00Z'},
...        {'event': 'message', 'from': 'cn', 'name': 'w1', 'at': '2026-01-01T11:00:00Z'},
...        {'event': 'intent', 'name': 'w1', 'at': '2026-01-01T12:00:00Z'}]
>>> [(e['type'], e['source'], e['target'], e['data']['count'])
...  for e in from_events(log)(rows)]
[('messaged', 'session:a1', 'session:b2', 2), ('told', 'owner:me', 'session:b2', 1)]

crowsnest.relations.from_lineage(graph)[source]#

A reader of the spawn forest (crowsnest.lineage.graph()’s result): one spawned link per edge, parent to child, keeping the edge’s own confidence.

A parent that has exited is still a node (alive false), as it is in the forest: a fleet whose dispatcher left is still a fleet.

>>> forest = {'nodes': [{'name': 'boss', 'session_id': '', 'alive': False},
...                     {'name': 'w1', 'session_id': 'b2', 'alive': True}],
...           'edges': [{'parent': 'boss', 'child': 'w1', 'confidence': 'recorded',
...                      'child_session_id': 'b2', 'parent_session_id': ''}]}
>>> found = list(from_lineage(forest)([]))
>>> found[0]['id'], found[0]['data']['status']
('session:~boss', 'exited')
>>> found[1]['source'], found[1]['target']
('session:~boss', 'session:b2')

crowsnest.relations.from_references(rows)[source]#

What each session’s own words refer to: one node per issue, pull request, page or repository, and a mentions link to it. An issue or pull request also brings its repository, with an of_repo link: a session working from a folder that is no checkout is then still tied to what it works on (refers_to_repo, derived).

Reads a row’s links (crowsnest.links resolved them when the roster was read), so a row read without links yields nothing. A reference keeps the state a refresh gave it (open, closed, merged), when the row has one.

>>> found = list(from_references([{'session_id': 'a1', 'label': 'parser', 'links': [
...     {'type': 'pr', 'url': 'https://github.com/i2mint/mergeset/pull/27',
...      'text': 'mergeset#27', 'at': '2026-01-01T10:00:00Z'}]}]))
>>> found[0]['id'], found[0]['data']['label']
('pr:i2mint/mergeset#27', 'mergeset#27')
>>> [(e['type'], e['target']) for e in found if 'source' in e]
[('mentions', 'pr:i2mint/mergeset#27'), ('of_repo', 'repo:i2mint/mergeset')]

Every session, with the machine it runs on, the folder it works in and that folder’s repository.

crowsnest.relations.from_verdicts(rows)[source]#

What triage says each session needs: its group on the node, and one waits_on_owner link per session that needs its person.

Reads a row’s verdict (crowsnest.triage.classify() puts one on every row); a row without one yields nothing, so a roster that was never classified still makes a graph. A verdict read from the session’s own ledger or from the registry is recorded; one read from its last words is observed.

crowsnest.relations.infer(links, *, rules=(Rule(name='works_on', path=('works_in', 'in_repo'), closure=False, symmetric=False), Rule(name='refers_to_repo', path=('mentions', 'of_repo'), closure=False, symmetric=False), Rule(name='same_repo', path=('works_on', '~works_on'), closure=False, symmetric=True), Rule(name='same_folder', path=('works_in', '~works_in'), closure=False, symmetric=True), Rule(name='same_reference', path=('mentions', '~mentions'), closure=False, symmetric=True), Rule(name='descends_from', path=('~spawned',), closure=True, symmetric=False), Rule(name='reaches', path=('messaged',), closure=True, symmetric=False)), max_fanout=12)[source]#

The links rules derive from links, and what was left out.

Returns (derived, skipped). Every derived link is inferred, names its rule in by and lists under via the nodes it went through (the first VIA_LIMIT paths’ worth, with paths counting them, up to TRAIL_LIMIT). skipped lists each hub a rule did not walk through: {"rule", "node", "fanout"}. A closure rule (spawned, messaged walked again and again) stops at a hub on every hop, the first included: a dispatcher that messaged a hundred sessions is one hub, not ten thousand chains.

>>> base = [link('spawned', 's:a', 's:b'), link('spawned', 's:b', 's:c')]
>>> derived, _ = infer(base, rules=[Rule('descends_from', ('~spawned',), closure=True)])
>>> [(d['source'], d['target'], d['data']['via']) for d in derived]
[('s:c', 's:a', ['s:b'])]
>>> many = [link('works_in', f's:{i}', 'folder:x') for i in range(5)]
>>> derived, skipped = infer(many, max_fanout=3,
...     rules=[Rule('same_folder', ('works_in', '~works_in'), symmetric=True)])
>>> derived, skipped
([], [{'rule': 'same_folder', 'node': 'folder:x', 'fanout': 5}])
