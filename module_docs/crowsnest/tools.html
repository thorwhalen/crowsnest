crowsnest.tools

The operations, as plain functions: JSON-able arguments in, JSON-able dicts out.

This is the single list every surface dispatches from. The CLI renders these; an MCP server or an HTTP endpoint would reference them by name and get the same dicts. Nothing here prints, exits, or knows which surface called it.

>>> roster(home='/nonexistent-dir-for-doctest')['counts']
{'waiting': 0, 'busy': 0, 'shell': 0, 'idle': 0, 'other': 0}
crowsnest.tools.report(*, home: str | Path | None = None, all_homes: bool = False, config: str | Path | None = None, made_at: str | None = None, title: str = 'crowsnest') → dict[source]

The roster as one self-contained HTML page: crowsnest.report.render_report() over what roster() returns.

made_at is the moment the snapshot claims to be from; it defaults to now, but a caller that wants byte-stable output passes it explicitly – this is the one crowsnest function that stamps a generation time. all_homes reads every configured home, and each row’s home field (present when it does) shows up in the page.

crowsnest.tools.resolve(session: str, *, home: str | Path | None = None, all_homes: bool = False, config: str | Path | None = None) → LiveSession[source]

The live session a human means by session.

Tried in order: the exact registry name, a unique name prefix, a unique session-id prefix, the pid. name@home names a session in one home when several homes are read. Raises KeyError naming the candidates when nothing or too much matches – an ambiguous pick is a wrong pick half the time.

crowsnest.tools.roster(*, home: str | Path | None = None, all_homes: bool = False, config: str | Path | None = None, activity: bool = True, text_limit: int = 240) → dict[source]

Every live session, most urgent first, each with a clipped view of its activity.

activity=False skips the transcript tails and answers from the registry alone – instant, and enough to know who is waiting. all_homes reads every configured home (see crowsnest.config) and stamps each row with its home’s name.

crowsnest.tools.sessions(*, home: str | Path | None = None, all_homes: bool = False, config: str | Path | None = None) → list[LiveSession][source]

The live sessions of one home, or of every configured home when all_homes.

With all_homes each record carries the name of the home it came from, and a home marked remote in the config is read with a freshness rule instead of a pid check. Rows keep the roster order within each home; homes come in config order.
